## 本轮实际发现并修复的缺陷

1. **原帳票引用再次发行风险**：原正式帳票订正/无效后，新命令可能使用原 sourceKey 再次创建文档。改成只允许活跃原件幂等复用；旧引用被订正或取消时必须进入专用订正流程。增加负面测试，保障 sale 与正式编号不重复。
2. **客户资料静默覆盖**：只更新名称时可能将原地址清为空。改为缺省字段保留旧地址，增补回归测试。
3. **操作 ID 的不完整验证**：命令服务在操作重放时只检查 action 类型。现在引入 SHA-256 请求指纹及 actor 验证，区分同 ID 不同内容，避免将错误请求当作已完成。
4. **写入测试引起的语法/规则错误**：更改操作 ID 签名时发现 JavaScript 变量重名和 Firestore Rules 残留重复段，导致 CI 失败。已在开发分支修正，复测以最新提交的 CI 为准。该问题说明不能把曾经通过的旧 CI 结果当作当前提交的准入凭证。

## 重复代码和精简结论

- 冻结 `legacy-pdf/source/index.html` 及 16 个原版 JS 文件是**有意保留的历史渲染依赖，不属于可随意删除的重复运行代码**；直接裁剪会破坏 PDF 像素一致的验收结果。
- 新业务各层边界：`core/business.js` 只做业务；`services/command-service.js` 负责命令 → 多记录事务；`storage/firestore-repository.js` 负责权限/审计/版数；`integrations/platform-settlement.js` 只读月结核对；`core/schedule-calendar.js` 独立展示施工日程；`pdf/frozen-document.js` 只读下载。职责不同，**不能仅因字段/函数名相似就删除**。
- 目前没有证据表明新的 `src/` 目录存在应直接删除的完整重复模块。清理标准：先画出入口、调用、字段、模拟与旧兼容引用；确认无实际引用、无历史需求后才移除，并要求全量回归 CI。
- 旧版单 HTML 的大体积 UI/业务代码不作为新 UI 主入口；新界面将调用独立 core/service，不继续使用旧页面全局函数和重写式 wrapper。
