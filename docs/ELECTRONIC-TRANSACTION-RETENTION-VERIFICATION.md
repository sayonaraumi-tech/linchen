# 電子取引データ保存・実務検証票（2026-11-16）
対象：月輪合同会社の事業用受発注・請求・領収・仕入・銀行／プラットフォーム取引。**本書は合格証明書ではなく、未実施項目を含む検証票です。**

## 適用分類
- メール・ポータル・プラットフォーム等で受領した請求書・領収書・取引明細は、内容により電子取引データとして原本の保存が必要。
- 自社発行PDFも相手方へ電子送付した取引データの保存対象になり得る。
- 銀行CSVは会計照合証跡として保存を推奨し、法的保存区分・期間は証憑内容に応じ税理士確認。
- スキャナ保存、電子帳簿、電子取引は区分が異なり、単なるPDF再生成や画面キャプチャは電子取引原本保存の代わりにはならない。

## 真実性
- [ ] 受領原本のファイルバイト・取得日時・発行者・取引先・取引日・金額を保持し、後から新PDFを出力して原本を上書きしない。
- [ ] タイムスタンプ、訂正削除履歴システム、又は正当な理由のない訂正削除を防止する事務処理規程等、利用する適法な措置を決めて運用・証明する。
- [ ] 取消・値引き・修正は元の書類と改訂版を関連づけ、発行済み番号・年月日・金額・変更理由・実行者を追跡できる。

## 可視性
- [ ] 必要なディスプレイと操作説明資料を整備。
- [ ] 日付・金額・取引先の検索、範囲条件と複数条件の結合（適用例外を含む）を検証。
- [ ] 税務調査時に原本を閲覧・ダウンロードし、帳票番号と売上・入金・銀行明細へのリンクを確認。
- [ ] 自社開発ソフトのシステム概要資料を用意。

## 保存性と復元
- [ ] Firestoreデータベースの実運用バックアップ設定、保持期間、IAM、復元先の分離を確認。
- [ ] PDF/CSV原本と出所・メタデータをDBバックアップとは別に保全（Firestore DBバックアップだけでは外部原本の保存は証明できない）。
- [ ] 実際に別の非本番環境へ復元し、件数・残高・番号・原本ハッシュ・監査履歴の突合結果を保存。
- [ ] 権限を持つ職員と税理士による最終適用確認、実運用の証拠を保存。
