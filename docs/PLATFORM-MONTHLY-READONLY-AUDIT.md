# 月次平台手续费：内部只读核对与代码精简验收

日期：2026-11-13；仅适用于 `linchen` 新系统开发分支。原 `geruninn`、生产 Firestore、真实银行、帳票历史均不改动。

## 业务确认

| 渠道 | 实际结算 | 内部核对用途 | 是否写入会计业务 |
| --- | --- | --- | --- |
| NP | 每月官方手续费請求書，GMO 公司银行卡自动扣款 | 官方应扣金额 vs 银行实际扣款；内部预估差额另列 | **否** |
| Stripe | 一个月一批/按官方结算批次汇入银行卡 | 官方 gross/refund/fee/adjustment/net 与该月银行入金，比较内部预估手续费 | **否** |
| ATO | 一个月一批/按官方结算批次汇入银行卡 | 与 Stripe 类似，按各自官方月次结算证据核对净入金与费差 | **否** |

**核对先后：** 官方平台月度請求書/精算明细 → 明确对应的 GMO 银行流水 → 内部预估手续费。差额必须明确显示，禁止为了凑平而修改账本。没有官方月次明细时，不用假定固定手续费率反推。

公式：
- NP：银行当月对应扣款合计 − NP 官方应扣手续费；NP 官方手续费 − 内部预估手续费。
- Stripe/ATO：官方交易总额 − 退款 − 官方手续费 + 官方调整 = 官方净汇款金额；银行对应汇入合计 − 官方净汇款金额；官方手续费 − 内部预估手续费。

这里的“月份”由官方对账的**计费或结算期间**确定，银行扣款/入金日可以落在次月，不以银行月份强行重划官方期间。一个银行月次转账对应整批结算，不以每个订单在银行逐笔入账。

## 安全边界与代码清理

- `src/integrations/platform-settlement.js` 改为零依赖、独立、只读 `reconcileMonth`/`monthlyReport`。移除旧设计中的逐笔订单核对与记账指令 `normalizeStatement`/`reconcile`/`postingRules`，因为不符合当前实际平台使用方式。
- **不存在对** `business.js`、`command-service.js`、`firestore-repository.js` **的引用或写入接口**，平台内部审核结果不能自动写 `sales/payments/expenses/bankTransactions`。
- 银行证据需有明确 account、direction、row ID；重复银行 ID 不能按两笔计算。缺少银行凭证的金额返回 `null`，不默认为 0 円或“已核对”。
- 已按模块检查核心、银行导入、只读视图和 Firestore 服务，平台内部核对模块没有被用于自动财务记账。信用卡月度合并业务不作为当前优先级。
- 代码仅更新 GitHub 开发分支上核对模块和相关测试，未清除原系统兼容层。全仓库历史代码若无法证实无引用/无同步影响，不能盲删；正式数据也不允许被启动时自动清理/覆盖。
